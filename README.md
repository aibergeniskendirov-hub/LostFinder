# LostFinder

MVP-сайт для поиска потерянных и найденных вещей в Narxoz University.
Студенты и сотрудники публикуют объявления о потерянных и найденных вещах,
а встроенный ИИ сравнивает смысл описаний и предлагает возможные совпадения.

Весь проект на JavaScript (без Python и TypeScript).

## Стек

- **Клиент:** React + Vite, Bootstrap 5 + собственный CSS.
- **Сервер:** Node.js + Express, JavaScript ES Modules.
- **База данных:** SQLite (`better-sqlite3`), хранится в файле на диске.
- **ИИ:** [Transformers.js](https://huggingface.co/docs/transformers.js) (`@huggingface/transformers`),
  модель `Xenova/paraphrase-multilingual-MiniLM-L12-v2` — бесплатная, работает полностью
  локально на CPU, без GPU и без платных API. Модель multilingual и хорошо работает
  с русским и английским языком.

## Необходимая версия Node.js

**Node.js 18.20+ или 20+** (разработано и проверено на Node.js 24). Нужен npm
(устанавливается вместе с Node.js), ничего больше — ни Python, ни отдельная база
данных ставить не нужно.

## Установка и запуск

### Windows и macOS — одинаковые команды

```bash
# 1. Установить зависимости клиента и сервера
npm run install:all

# 2. Скопировать файл с переменными окружения
cp .env.example server/.env        # macOS/Linux
copy .env.example server\.env      # Windows (cmd)

# 3. Загрузить демоданные (по желанию, но для демонстрации рекомендуется)
npm run seed

# 4. Запустить клиент и сервер одной командой
npm run dev
```

После этого:

- Клиент (сайт): **http://localhost:5173**
- Сервер (API): **http://localhost:3001**

Остановить оба процесса — `Ctrl+C` в терминале, где выполнен `npm run dev`.

> **Важно про первый запуск.** При самом первом запросе к ИИ-поиску (или при
> запуске `npm run seed` / `npm run evaluate`) сервер скачивает модель эмбеддингов
> (~118 МБ) с Hugging Face Hub и кэширует её на диске — для этого **нужен интернет**.
> Повторные запуски уже используют кэш и работают офлайн. Пока модель грузится,
> кнопка «Найти совпадения» вернёт понятное сообщение «модель ещё загружается» —
> это нормально, просто подождите несколько секунд и попробуйте снова.

## Демоданные и проверка качества

```bash
npm run seed       # загружает ~30 демо-объявлений (10 размеченных пар + 10 "похожих, но неверных")
npm run evaluate    # считает Recall@5: смысловой поиск против поиска по ключевым словам
```

`npm run seed` идемпотентен: повторный запуск не создаёт дубликатов (проверяет
отметку в таблице `seed_meta`). Данные сохраняются в файле SQLite и переживают
перезапуск сервера.

Пример реального вывода `npm run evaluate` на этом демо-наборе (10 размеченных пар,
20 запросов в обе стороны):

```
Смысловой поиск   Recall@5: 20/20 = 100.0%
Поиск по словам   Recall@5: 16/20 = 80.0%
```

**Это не гарантия качества**, а предварительная оценка на маленькой синтетической
выборке — смотрите предупреждение, которое скрипт печатает сам.

## Где используется ИИ и как считается «Оценка сходства»

ИИ используется только в одном месте: при нажатии кнопки «Найти совпадения» сервер

1. получает эмбеддинг (вектор из 384 чисел) текста «название + описание» текущего
   объявления и каждого активного объявления противоположного типа (потеряно ↔
   найдено, закрытые исключаются);
2. считает косинусное сходство между векторами — это и есть смысловое сходство;
3. добавляет небольшие бонусы, если совпала категория, совпало место или даты
   события близки (константы и веса — в `server/src/config/matching.js`,
   см. `WEIGHTS`, `MATCH_THRESHOLD`, `DATE_PROXIMITY_WINDOW_DAYS`);
4. показывает до 5 кандидатов, чей итоговый балл выше `MATCH_THRESHOLD`, вместе
   с перечнем конкретных причин («совпала категория», «совпало место», «близкие
   даты»).

Эмбеддинги вычисляются один раз на объявление и кэшируются в таблице `embeddings`
вместе с версией модели (`MODEL_VERSION`) — при следующем поиске они не
пересчитываются, пока модель не изменится.

Балл подписан как «Оценка сходства» намеренно — это не вероятность и не процент
уверенности, а число для сравнения кандидатов между собой. Интерфейс явно
сообщает: «Рекомендация ИИ не подтверждает владельца» — окончательное решение
о передаче вещи всегда остаётся за людьми, после личной проверки.

Если модель ещё не загрузилась или недоступна, сервер возвращает явную ошибку
(«модель ИИ недоступна» / «модель ещё загружается»), а не подменяет ИИ-поиск
обычным поиском по ключевым словам без предупреждения.

## Ограничения MVP

- Полноценной регистрации и входа нет: вместо этого — секретный код управления,
  который показывается автору ровно один раз после публикации.
- ИИ сравнивает только текст (название + описание). Фотографии в объявлениях
  только отображаются и не анализируются никаким способом.
- Поиск совпадений рассматривает только *активные* объявления противоположного
  типа; закрытые («возвращено») исключаются из выдачи.
- Оценка качества (`npm run evaluate`) основана на 10 синтетических парах — это
  достаточно, чтобы увидеть направление эффекта, но не для строгого вывода о
  качестве на реальных данных.
- Нет чата, email-уведомлений, распознавания фотографий, Docker и
  микросервисов — по условиям задания это сознательно не входит в MVP.
- Rate limit на попытки ввода кода — по `listing_id` (не по IP), этого достаточно
  для учебного MVP, но не заменяет полноценную защиту от перебора в продакшене.

## Сценарий демонстрации преподавателю (2-3 минуты)

1. **Покажите ленту** (`npm run seed` уже выполнен) — отфильтруйте по типу
   «Потеряно» и категории «Сумки», покажите карточки.
2. **Создайте объявление** — нажмите «+ Добавить объявление», заполните форму
   (например, «Потерян чёрный рюкзак с ноутбуком» в аудитории), попробуйте
   отправить с пустым названием — покажите, что форма не даёт отправить. После
   успешной публикации покажите секретный код и предупреждение, что он
   показывается один раз.
3. **Запустите ИИ-поиск** — откройте любое объявление из размеченной демо-пары
   (например, «Потерян чёрный iPhone 13»), нажмите «Найти совпадения» — покажите
   найденную карточку, «Оценку сходства» и причины совпадения, обратите
   внимание на дисклеймер про подтверждение владельца.
4. **Закройте объявление** — введите неверный код (покажите отказ), затем
   настоящий код — объявление переходит в статус «Возвращено».
5. **Если есть время** — покажите `npm run evaluate` в терминале: сравнение
   смыслового поиска и поиска по ключевым словам на реальных измеренных числах.
